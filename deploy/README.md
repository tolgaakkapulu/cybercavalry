# Deployment Guide

This directory holds everything you need to bring CYBERCavalry up on a
production host. Pick the folder that matches your target operating
system; the cross-platform pieces live at this level.

## Directory Layout

```
deploy/
├── README.md                       ← You are here
├── prepare_offline_bundle.py       ← Cross-platform: downloads Python wheels
├── wheels/                         ← Generated by prepare_offline_bundle.py
├── wheels.py39.lock.txt            ← Lock file for the Python 3.9 wheel set
├── wheels.py311.lock.txt           ← Lock file for the Python 3.11 wheel set
│
├── linux/                          ← RHEL/AlmaLinux/Rocky + Debian/Ubuntu
│   ├── INSTALL_RHEL.md
│   ├── install_rhel.sh
│   ├── update_rhel.sh
│   ├── INSTALL_DEBIAN.md
│   ├── install_debian.sh
│   ├── update_debian.sh
│   └── cybercavalry.service        ← systemd unit (shared)
│
└── windows/                        ← Windows Server 2019/2022 / Windows 10+
    ├── INSTALL_WINDOWS.md
    ├── install_windows.ps1
    ├── update_windows.ps1
    └── cybercavalry-service.xml    ← WinSW service definition
```

## Pick Your Path

| Target                              | Guide                                                       | Runner   | Service manager | Firewall  |
| ----------------------------------- | ----------------------------------------------------------- | -------- | --------------- | --------- |
| **RHEL 9.x / AlmaLinux / Rocky 9**  | [`linux/INSTALL_RHEL.md`](linux/INSTALL_RHEL.md)            | gunicorn | systemd         | firewalld |
| **Debian 12+ / Ubuntu 22.04+**      | [`linux/INSTALL_DEBIAN.md`](linux/INSTALL_DEBIAN.md)        | gunicorn | systemd         | ufw       |
| **Windows Server 2019 / 2022**      | [`windows/INSTALL_WINDOWS.md`](windows/INSTALL_WINDOWS.md)  | waitress | WinSW           | Defender  |
| **Windows 10 / 11 (dev + testing)** | [`windows/INSTALL_WINDOWS.md`](windows/INSTALL_WINDOWS.md)  | waitress | WinSW (optional) | Defender |

Arch, Alpine and other Linux distros aren't shipped with ready-made
scripts, but either `linux/INSTALL_RHEL.md` (SELinux distros) or
`linux/INSTALL_DEBIAN.md` (systemd + no SELinux) is close enough — swap
the package manager (`pacman`, `apk`, ...) and adjust the firewall
tooling to match.

## Prepare the Offline Bundle (Do This First)

Whether you deploy on Linux or Windows, the target host is usually
firewalled off from the internet. Run this **on a connected workstation
first** to fetch every Python wheel the target will need:

```bash
python deploy/prepare_offline_bundle.py             # both Python 3.9 and 3.11
python deploy/prepare_offline_bundle.py --py 39     # only 3.9
python deploy/prepare_offline_bundle.py --py 311    # only 3.11
```

The wheels land in `deploy/wheels/py39/` and `deploy/wheels/py311/`.
Copy the whole `deploy/wheels/` tree to the target machine alongside
the rest of the project.

## Cross-Platform Notes

- **Python version**: 3.9, 3.11 or 3.12. Only 3.9 and 3.11 are shipped
  in the offline wheel bundle by default — add another with
  `prepare_offline_bundle.py --py 312`.
- **WSGI server**: `gunicorn` on Linux, `waitress` on Windows. The
  `requirements.txt` uses `sys_platform` markers so the right one
  installs automatically per host.
- **Redis**: optional everywhere. When absent, the platform falls back
  to Django's `DatabaseCache` — rate limits and lockouts still work.
- **HTTPS**: the platform serves TLS directly on port 8443 by default.
  Front with nginx / Caddy / IIS only if you need name-based virtual
  hosting or offloading.
- **Firewall**: open TCP/8443 (or your custom port) to the callers that
  need to consume `/api/blacklist/*` and to your operators' browsers.
