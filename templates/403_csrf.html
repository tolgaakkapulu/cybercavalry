{% load static %} {% comment %} CSRF failure page — overrides Django's built-in plain-text 403. Django's `csrf_failure` view looks for a template named exactly `403_csrf.html` (django.views.csrf.CSRF_FAILURE_TEMPLATE_NAME) and falls back to a hard-coded string only when it is missing. That fallback is what operators were seeing: three unstyled sentences, translated into whatever language the browser asked for, ending in "More information is available with DEBUG=True" — advice nobody can act on in production. Rendered WITHOUT context processors (`csrf_failure` calls `template.render(dict)` with no request), so nothing here may depend on them: no `{{ request }}`, no theme flag, no branding beyond a `default`. The page therefore renders in the dark palette, like the other error pages. Context Django provides: `reason`, `no_referer`, `no_cookie`, `DEBUG`. Those booleans are the only way to tell the operator WHICH failure mode they hit, so the advice block branches on them instead of printing one generic paragraph. The raw `reason` string stays behind DEBUG, as in Django's own template: it names internal state. The stable code (CSRF_VERIFICATION_FAILED) is always shown, because an operator filing a ticket needs something to quote. {% endcomment %} 403 Security Check Failed — {{ platform_name|default:"CYBERCavalry" }}

What to try

  • Allow cookies for this site. Private-browsing rules, a tracker blocker or a company policy can drop them.
  • Check the clock on your machine. A date far in the past or future makes the browser treat a fresh cookie as expired.
  • Then open the sign-in page again from the button below.

What to try

  • Turn off referrer stripping for this site in your privacy extension or browser settings.
  • Reach the site by its normal address, not through a redirect service or a shortened link.

Most likely cause

  • The page had been open for a while. The token is tied to a session that has since been replaced.
  • You came back with the Back button after signing out, and the form still carried the old token.
  • Two tabs. Signing in on one tab invalidates the form sitting in the other.

Opening the sign-in page fresh issues a new token and clears this.
